## v0.8.5

自 v0.8.4 起（dsh-ui-taste 跨机导入无法加载的根因修复 + 启动嫌疑定位只扫本次启动窗口）：

### 修复

- **跨机导入的本地插件无法加载（dsh-ui-taste 实证，`ERR_MODULE_NOT_FOUND: Cannot find package '@deepseek-ai/dsh-settings'`）**：根因是导入副本的稳定落点 `<dshHome>/local-plugins` 位于 profiles 工作区树之外——dsh 的 loader 按 Node ESM 规则从插件**真实路径**上溯 node_modules，旧落点上溯链找不到提升的 `profiles/node_modules`（@deepseek-ai/dsh-settings 等官方 peer 依赖所在），插件加载失败。修复：①稳定副本落点改为 `<dshHome>/profiles/local-plugins`（上溯链命中 profiles/node_modules，peer 依赖可解析）；②新增旧落点自动迁移——spec 仍指向旧落点的副本迁移到新落点并改写 spec（历史版本遗留的「副本在但加载失败」状态导入/更新时自动修复）。
- **启动嫌疑定位误判历史错误（restrict-discipline 被历史日志误禁用、dsh-ui-taste 被记下数天前的陈旧原因）**：日志轮转失败时统一日志不换文件、历史启动现场持续累积，而嫌疑解析（parseBootLogSuspects/bootSuspectReasons/unresolvedBundleNames）以 offset=0 扫描全量日志，把历史启动的报错误判为本轮嫌疑。修复：轮转时记录本次启动的日志基线（lastBootLogBase），offset=0 默认只扫基线之后的追加段——嫌疑名单与禁用原因均来自本次启动现场。

### 变更

- 无。

### 移除

- 无。

- **本地插件跨机导入后版本陈旧（dsh-ui-taste 本地 0.2.1、导入新机后仍显示 0.2.0）**：根因是

## v0.8.3

自 v0.8.2 起（三项改进：mac 本地插件重选仍未加载续查、日志页完整显示、禁用优先于版本回退）：

### 修复

- **mac 重选本地插件后仍未加载（R2 定案）**：待重指定插件重选目录时，若历史记录 bundled=false（源机未激活），重选事务只清记录、不把插件加回激活清单——spec 与 node_modules 均已就位但 harness 从未加载它，且无任何提示。现在**重选 = 显式激活**：无论历史 bundled 真假，重选一律补进 `dsh.profile.bundles`。
- **mac 旧服务进程不退出导致新配置永不加载**：`killServer` 对端口监听进程只发一次 SIGTERM；旧进程未退出时重启校验误判「端口已有可用服务」而跳过重启，插件重选/更新/导入的新配置不生效。现 SIGTERM 后轮询端口释放，仍存活时 SIGKILL 兜底（与 Windows taskkill /F 语义对齐）。
- **日志页内容不完整（三处丢失点）**：前端 4000 行 DOM 裁剪把最早写入的行静默丢弃；日志轮转后 offset 跳到新文件末尾，把「轮转后新写入的行」整体跳过（mac 每次服务重启都轮转）；轮转归档 .1/.2/.3 不参与展示，轮转前的历史从页面消失。现在日志页 = 归档（旧→新）+ 基础文件完整拼接，检测到轮转自动清空视图重载，清空日志一并删除归档。

### 变更

- **禁用优先、回退兜底**：更新 harness / 导入插件后服务启动失败时，先按启动日志点名禁用肇事插件；未奏效或无点名嫌疑时禁用全部已激活的用户插件再试，仍失败才回退版本。冷启动失败同样先尝试「禁用肇事插件保留当前版本」，都失败才恢复 LKG 旧版本。禁用只摘除激活清单并记录原因，可在关于页逐个重新启用。
- 本地插件重选/更新成功弹窗：所选目录缺少 node_modules（依赖未安装/未构建）时附排查提示；终态日志逐 profile 输出并记录 node_modules 链接状态。

### 移除

- 日志页 DOM 行数裁剪（与「完整显示所有已写入内容」冲突）。

## v0.8.2

自 v0.8.1 起（mac 用户实证：导入的本地插件重选目录后仍不加载、日志页空白）：

### 修复

- **mac 本地插件重选后不加载（dsh-ui-taste 实证）**：待重指定插件重选目录时，若所选目录版本与 node_modules 残留副本一致，前端把「版本相同」误判为「无需操作」而跳过执行（只提示「已经是最新版本」），pending 记录 / bundles 激活 / link: spec 从未修复 → 插件永不加载。现在待重指定行任何目录选择都走「重新指定」确认并执行完整重链接事务（清待重指定 + 恢复激活 + 改写来源 + 安装 + 重启校验）。
- **mac 统一日志页空白**：每次拉起服务前的日志轮转把 `dsh-systray.log` 改名 `.1`，mac（POSIX）允许改名打开中的文件，旧句柄继续写入 `.1` 而基础文件消失 → 日志页（只读基础文件）空白、启动日志扫描（嫌疑插件自愈判定）随之失效。轮转成功后现会重开统一日志句柄，基础文件即时重建；Windows（文件锁走保留路径）不受影响。

### 变更

- 本地插件重选/更新成功后在日志记录一行终态快照（依赖 spec、bundles 激活、待重指定、禁用状态），便于此类问题凭日志一次定案。

### 移除

- 无。

## v0.7.3

本版自 v0.7.2 起：macOS 四项修复——菜单栏图标尺寸对齐系统惯例、日志落盘加固、开机自启动改为系统级可靠注册、退出流程不再阻塞系统关机/重启。

### 新增

- **macOS 关机/注销感知**：监听系统关机/重启/注销通知，退出流程自动跳过「是否停止后台服务」询问直接放行（系统退出时会自行回收进程），不再阻塞关机/重启；快速用户切换切回后恢复正常的退出询问。
- **日志落盘加固**：日志目录创建/打开失败时自动回退到系统临时目录（此前失败完全静默、表现为"日志为空"）；启动首行固定记录版本/pid/日志完整路径；应用日志同时写 stderr（Console 可查，诊断兜底）。

### 变更

- **macOS 开机自启动注册方式**：LaunchAgent 改为 `/usr/bin/open` 打开 .app（此前直接执行包内裸二进制，缺 bundle/LSUIElement 上下文，登录时启动异常——自启"失效"根因）；加载改用 `launchctl bootstrap/bootout`（`load/unload` 已废弃）并校验错误；plist 增加 `LimitLoadToSessionType=Aqua` 与 `ProcessType=Interactive`。
- **macOS 自启动状态如实反映**：设置页开关状态校验 launchd 实际注册（`launchctl print`），不再以 plist 文件存在与否为准。
- **老版本自启条目自动升级**：启动自愈把残留的旧形态 plist（裸二进制 exec / 无 `--autostart`）重写为 open .app 形态，下次登录生效。

### 修复

- **macOS 菜单栏图标尺寸**：画布由 22pt 收至 18pt、图形占比提至 0.9（图形约 16.2pt，对齐系统菜单栏图标 16–18pt 惯例；此前 22pt 画布占满菜单栏且图形偏小）。
- **macOS 退出不阻塞系统关机/重启**（见上「关机感知」）。
- **macOS 开机自启动失效**（见上「注册方式变更」）。
- **macOS 日志为空**：目录回退链 + 非静默 + stderr 双写 + 启动首行（定位日志路径与写入是否生效）。

### 移除

## v0.7.2

本版自 v0.7.1 起：恢复反馈更即时（会话/文件恢复完即显示已完成）、重置不再重复查版本且可重装当前版本、托盘菜单宽度自适应并收缩、恢复插件后的「自愈」文案澄清，以及 macOS 全面适配（启动/菜单/退出/运行依赖/图标规范）。

### 新增

- **重置允许重置到当前版本**：目标下拉提供「不高于当前运行版本」的官方版本（含当前版本=同版本重装，标注「（当前）」），默认仍取其中最新稳定版。
- **托盘菜单宽度自适应**：每次打开前比对菜单文本，内容变化时重建菜单让系统按当前文本重新测量宽度（文本缩短也能收窄），且不低于启动时默认宽度；同时修正菜单项 UTF-16 长度计算（原误用字节数导致中文菜单测量错误）。
- **会话记录 / 文件目录恢复完成即提示**：非插件类恢复任务完成后立即发布「恢复完成」并显示 ✓ 徽标，不再等待整批服务收尾（插件类仍以批末启动校验为准）。
- **macOS 运行依赖自动就绪**：不再依赖 Homebrew；缺失时自动下载便携 Node.js 并安装 pnpm 到用户目录。
- **工具下载多镜像自动切换**：Node / pnpm / 7-Zip 等下载单源超时自动切换下一镜像（Node：官方→npmmirror→华为云；npm registry：npmmirror→官方，收紧 fetch 超时快速失败切换）；可用环境变量 `DSH_NODE_MIRROR` / `DSH_NPM_REGISTRY` 固定单一来源。
- **macOS 图标按系统规范缩放**：菜单栏图标按 22pt 画布 + 图形留白绘制；.app 图标（Finder/Dock）整体缩小并四周留白，视觉尺寸对齐微信/Firefox 等常见应用。

### 变更

- 重置执行不再查询版本：目标与默认值在弹窗打开时一次查证（`GetResetVersions`），点击「开始重置」后不再出现「正在查询官方可用版本」阶段，也无需网络即可进入安装。
- 恢复插件后的「自愈」措辞改为「启动服务并校验插件兼容性」：校验阶段（必然执行）不再以「自愈」命名，仅真正发生「禁用冲突插件 / 回退」时才出现自愈语义；导入页相关提示与日志同步。
- 托盘状态行（服务失败原因）在菜单中截断为 36 字，完整原因见设置页与日志，避免把托盘菜单撑得过宽。
- 托盘图标不再显示应用名文字（只显示图标，名称在悬停提示中）。
- macOS 窗口红点关闭只隐藏应用；Dock / ⌘Q 退出会询问是否停止后台服务后正常退出。

- macOS 点「设置」卡死：菜单动作不再于 AppKit 主线程内同步调用 Wails（避免互相等待死锁）。
- macOS 托盘点击无菜单：菜单常驻挂接 NSStatusItem（去掉临时挂接 + performClick 技巧）。
- macOS Dock / ⌘Q 退出无效：区分窗口关闭与真实退出，退出不再被吞掉。
- macOS 编译产物 .app 无图标：Info.plist 引用 wails 生成的 iconfile.icns。

## v0.7.1

本版自 v0.7.0 起累积了多项新机制：插件冲突不再整体回退、而是自动禁用并自愈；恢复/导入支持多任务队列与逐项取消；重置 Harness 时可自选更早的官方版本等。

### 新增

- **重置目标版本选择**：重置 Harness 时下拉可选官方已发布版本（仅提供早于当前运行版本的版本，默认选其中最新稳定版）；预发布通道版本以警示色标注，选中时提示与已装插件的兼容风险；当前版本识别失败或无更早版本时降级放行，按官方默认目标执行。
- **插件禁用 / 启用自愈**：更新、安装、删除插件或恢复导入后，若服务因某插件与当前核心不兼容而启动失败，自动「禁用」冲突插件（保留其文件与依赖声明，从 bundles 摘除并记录原因）后重启服务，不再整体回退；关于页展示禁用状态与原因，支持手动启用（启用后启动仍失败会自动重新禁用）。
- **本地插件更新**：插件行支持从本地目录选择新版本包，比对确认后覆盖更新（复用快照 / 回退 / LKG 管线）。
- **恢复 / 导入重构**：多个「恢复项」可先后入队、各自独立进度并逐项取消；批量共享自愈期间全局禁用恢复按钮；zip 解压支持中途停止（不再卡死）。
- **常规页「打开 Web UI」按钮**：服务运行时可一键打开 Web UI，指向服务实际运行端口（端口修改未重启的窗口期也正确）。
- **检查更新与重置同源**：npm 预构建形态的「检查更新」改为以 npm 已发布版本为准（与重置一致），修复 GitHub Release 领先/缺失 npm（如 0.1.2-rc.1 已发 npm、GitHub 无 Release）时两边版本不一致。
- **service_guard 增强**：启动前日志轮转留档（.1/.2/.3）、启动日志可疑插件定位、profile 依赖自动对齐重装、重启后健康校验窗口化与自动重试。

### 变更

- 恢复导入仅激活导出清单中列出的 bundles 覆盖名，不再合并源机的禁用列表与未激活依赖；恢复后的启动兼容由「禁用自愈」机制兜底。
- 重置流程文案修正为实际行为（停服 → 清空原目录 → 全新安装所选版本），移除旧描述「回退到上一个正常运行的版本」。
- 取消恢复按钮不再触发 3 秒后自动重启，改为保持禁用直至恢复任务真正结束。

### 移除

- 无用户功能移除（历史单一恢复槽由多任务队列取代，交互以「逐项恢复/取消」呈现）。
