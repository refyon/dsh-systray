## v0.8.13

自 v0.8.12 起（检查更新不再被供应链策略误判回退 + 插件变更改为「先登记、后应用」）：

### 修复

- **检查更新被供应链发布年龄校验误判为「安装失败」并整体回退**：pnpm 的 `minimumReleaseAge` 策略下，`pnpm add @deepseek-ai/dsh@<ver>` 在解析期已把整族写入 `minimumReleaseAgeExclude` 并完整装好（实测 497 包 / 13.7s），紧随其后的那句冗余 `pnpm install` 复核仍会拒绝这些 lockfile 条目（`ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`）——旧代码据 exit status 判定「依赖安装失败」并回退，用户只能改走「重置」绕道（重置路径只跑 add、不跑 install，所以能成功）。2026-09-11 09:20 实证。现：命中供应链策略拦截先以 `--config.minimumReleaseAge=0` 重试一次；仍失败时按**家族版本一致性**判定（顶层全部 `@deepseek-ai/dsh*` 已装到目标版本 + 入口包就位 → 视为安装成功继续启动校验，启动校验才是真正的验收关口），不再把策略复核当成安装失败。
- **更新 harness 后插件树仍停留在旧版本组合**：这就是「检查更新失败、必须重置并重新导入插件才能起来」的差异所在——重置+重新导入会重建每个 profile 的插件树，而检查更新此前装完就重启。现更新安装完成后、重启前逐 profile 执行 `pnpm install` 对齐（与导入恢复批末同一动作），把插件树按新 harness 重新解析；对齐失败不阻断更新，交由启动健康校验与插件自愈兜底，并在成功弹窗里如实说明。

### 新增

- **插件变更改为「先登记、后应用」（不再点一下就重启服务）**：点击插件的「更新」/「删除」只登记变更——不执行、不停服、不切走窗口，行内显示「待应用：…（重启服务后生效）」并给出「撤销」。
  - **关闭设置窗口时询问**：「有 N 项插件变更尚未应用（更新/删除需要重启后台服务才能生效），是否现在应用并重启服务？」选「立即应用并重启」即刻执行（进度窗口收尾时自动隐藏窗口）；选「稍后」则照常隐藏，变更留在待应用区。
  - **关于页常驻提示**：只要存在未应用变更，插件卡片顶部横幅持续显示「有 N 项变更尚未生效：…」并提供「立即应用」按钮；跨托盘重启保留（写入 `config.json`，启动时逐条校验，插件已被移除等失效条目自动丢弃）。
  - **一次重启完成全部变更**：应用时整批只停一次服务、逐项独立快照执行包操作，全部完成后统一做一次启动校验（此前每项操作各自停服 + 各自跑 ≥10s 健康校验窗口，N 项插件就是 N 次重启）。单项 pnpm 失败只回退该项（其余继续），批末校验失败才走自愈（禁用启动日志点名的嫌疑插件 → 兜底禁用全部已激活用户插件），仍失败才整批逆序回退。
  - 更新前处于「已禁用」的插件：应用时随本批解除禁用，由同一次启动校验判定——仍不兼容则自动重新禁用，不额外增加重启次数。
  - 「待重指定」「无依赖的自动禁用」行仍走记录清理，不触发停服与重启。
  - **按最后操作生效**：同一插件重复登记时同操作幂等、换操作覆盖（先登记删除、又登记更新 → 以更新为准）；应用前按当前插件状态重新校验，插件已不存在则跳过该项。
  - **重新导入即最后一次操作**：导入恢复成功后，本次恢复覆盖到的插件其先前登记的更新/删除一律作废，并在导入结果中说明（典型：先登记删除、随后又把它导回来，则不再删除）。
  - 互斥：harness 更新/重置进行中拒绝登记插件变更；应用进行中拒绝新登记与更新/重置 harness——两者都会停服并跑 pnpm。

### 变更

- macOS 红点关闭窗口走 Wails 的 HideWindowOnClose（不经 OnBeforeClose），无法在关闭前弹询问：mac 上依赖关于页横幅与「立即应用」入口（win 为关闭即询问）。

### 移除

- 无（单插件更新/删除入口保留原有绑定与按钮，仅执行路径并入「登记 → 应用」模型）。

## v0.8.12

自 v0.8.11 起（重置/更新失败不再留下停机与混装；依据 2026-09-10 macOS 日志复盘）：

### 修复

- **重置失败后服务停摆**：重置流程第 0 步就停服务，而各失败分支只弹窗返回（还原目录、不重新拉起），用户同时面对「重置失败」与「服务起不来」。2026-09-10 实证：22:29:47 重置安装失败还原目录后服务一直停着，直到 22:38:13 被后续更新拉起。现所有失败分支（形态不支持、目标缺失/非法、备份或建目录失败、安装失败、核心故障还原）统一走 `failReset`：先把服务拉回可用并校验，再弹窗报告；恢复失败时附「请点击重启服务」提示。
- **更新 harness 装出「新版插件 + 旧版核心包」混装树**：`snapshotHarness` 只把 `node_modules` 改名备份、`pnpm-lock.yaml` 仍留在原地，`pnpm add` 复用旧解析，家族核心包（只作为插件的 peer、未在根 `package.json` 声明）停在旧版本 → 启动时插件树 ESM 缺导出（`does not provide an export named assertNever / deepFreeze / snapshotJsonValue / requestImageDimensions …`）。现更新前丢弃旧锁文件（快照 `.dshbak` 仍可还原），强制全新解析。
- **家族钉版此前形同虚设**：旧的 `pnpm.overrides["@deepseek-ai/*"]` 名字通配在 pnpm 10.34.5 上实测不生效（同一份 `package.json` + `pnpm-workspace.yaml` 下家族仍解析到旧版本），且通配即便生效也会把同 scope 的 `@deepseek-ai/cordis`(4.x)、`schemastery`(3.x) 钉成 harness 版本而直接失败。现改为**逐包精确包名**钉版（包名取自锁文件 / `.pnpm` 目录名，含只作 peer 出现的核心包），更新与重置两条路径都钉整族到目标版本；钉版解析失败自动去掉钉版重试一次。
- **上游分批发布期间重置/更新必然失败**：家族依赖是 caret 范围（`^0.1.5-rc.1` 允许 `0.1.5-rc.2`），官方先发布一部分包时全新解析会选中半发布的新版本，随后在其缺失依赖上报 `ERR_PNPM_NO_MATCHING_VERSION`（2026-09-10 22:49 实测：`@deepseek-ai/dsh-chunked-list@^0.1.5-rc.2` 尚无对应包，数分钟后才发布；`dsh-sandbox-windows-acl` 同类）。逐包钉版把整族锁在目标版本，重置选「当前已装版本」时不再被上游半发布带崩。
- **改版后健康校验窗口过短**：混装树实测 22:38:13 启动、22:38:32 被 10s 窗口判成功并提升 LKG、22:38:58（启动后 45s）才刷出 `plugin tree failed to load` —— 短窗口不仅误判成功，还把唯一可回退的 LKG 当成已验证状态。现改版路径（harness 更新/重置/LKG 回退）健康校验窗口为 60s；冷启动仅在存在 LKG（上次改版尚未经冷启动验证）时用加长窗口，常规启动仍为 10s。

### 变更

- 安装失败提示按输出归类给出可执行原因：`ERR_PNPM_NO_MATCHING_VERSION`（上游未发布完整/目标版本不存在，稍后重试）与 `ERR_PNPM_META_FETCH_FAIL` / `Socket timeout` / `ECONNRESET`（registry 抖动）分别提示，并附 pnpm 输出尾部，不再只有 `exit status 1`。

### 移除

- 无。

## v0.8.11

自 v0.8.10 起（插件操作前置守卫 + 插件树确定性预检）：

### 新增

- **插件树确定性预检**：导入/更新插件在「依赖已对齐、服务尚未拉起」时，用 node 在 profile 目录里逐个 import 已启用的用户插件入口（与 cordis loader 同一解析锚点），把「启动必然失败」提前成「精确点名 + 自动禁用」。命中缺少具名导出（`does not provide an export named …`）、缺模块、语法错误的插件当场禁用并写入 `disabledPlugins`（关于页可见、可重新启用）；只缺 `apply` 的插件仅提示不禁用，避免误伤。此前的健康校验依赖启动日志 + 时间窗，加载错误可能晚于窗口关闭：2026-09-10 实测导入在 16:54:20 报 `service verified healthy`，8 秒后进程才死于 `assertNever` 缺导出。

### 修复

- **删除/更新插件被无关插件的悬空本地依赖打挂**：pnpm 的 remove/update/install 都要解析整张依赖图，profile 里任一个 `file:`/`link:` 依赖的目标目录不存在（工作区改名或移动、目录被删）就会让**整条命令**失败——2026-09-10 实证：删除 `dsh-codegraph` 被已随工作区迁移而失效的 `dsh-ui-taste` 本地路径打成 `exit status 0xfffff026`，界面只报「移除失败」，与被删插件毫无关系。现所有 profile pnpm 命令（remove / update / 本地插件更新 / 重启自愈对齐）之前先做本地依赖消毒：能取到稳定副本就改指副本（插件继续可用），取不到就摘除并记为「待重指定」。
- **失败原因不再只有 exit status**：删除路径与更新路径统一把 pnpm 原文尾部并入报错，并对 `ENOENT … scandir '<path>'` 做依赖归因，界面直接点名是哪个本地依赖失效（此前真实原因只落在日志里）。

### 变更

- 导入成功的提示语会附带预检产生的说明（被自动禁用的不兼容插件、疑似非标准 host 插件）。

### 移除

- 无。

## v0.8.10

自 v0.8.9 起（重置可到任意 npm 版本 + 重置启动受阻禁用自愈 + 更新快照覆盖 workspace）：

### 新增

- **重置目标可选任意官方 npm 版本**：重置弹窗下拉不再限于「不高于当前」——列出 npm 全部已发布版本（含更高版本=升级重装、预发布以警示色标注并提示兼容风险），默认选中当前版本（同版本重装）；`GetResetVersions`/弹窗文案同步更新。执行仍只装 npm 已发布版本（pnpm 精确版本安装，候选源不变）。
- **重置后启动受阻自动禁用插件（不回滚优先）**：与「更新 Harness」同一策略——启动健康校验失败先禁用启动日志点名的用户插件，仍失败再禁用全部已激活用户插件；任一成功即保留新版本、弹窗列出禁用清单（可于「关于页 → 已安装插件」检查更新或重新启用）；仅两级都失败（核心故障）才还原重置前目录——备份目录延迟到健康校验通过后再删除，失败可整体还原。

### 修复

- **更新失败回滚后残留 overrides 污染可用树**：快照 / 回滚 / 清理现在覆盖 `pnpm-workspace.yaml`（pnpm ≥ v10 只读该文件的 overrides）——更新失败回滚不再残留失败版本写入的 `@deepseek-ai/*` overrides 与 minimumReleaseAgeExclude，避免后续任何 `pnpm install` 把已回退的可用树再次拉向坏版本（0.1.5-alpha.1 实测案例）。
- **更新失败回滚文案被误读为「直接回滚」**：禁用嫌疑/全部插件后仍无法启动（核心故障）而回退时，弹窗原因明确为「已尝试排查并禁用不兼容插件，仍无法启动——疑为核心故障」；禁用阶段 splash 文案改为「服务启动受阻，正在尝试禁用部分插件…」（补 EN 译文）。

### 变更

- 重置下拉默认选中**当前版本**（同版本重装）而非最新稳定版；当前不在已发布列表时取最近可用稳定版（不高于当前优先），避免「重置」默认悄悄变成升级或降级。

### 移除

- 无。

## v0.8.9

自 v0.8.8 起（四项改进：日志复制 / 预发布通道复位 / 插件操作结果事件 / 更新不受其它插件拖累）：

### 修复

- **日志路径点击复制从未生效**：`kernel32.NewProc("CopyMemory")` 取不到导出符号（`CopyMemory` 是 C 头文件宏，kernel32 实际导出 `RtlMoveMemory`），惰性解析在点击调用时 panic、经 Wails 恢复后表现为「复制失败」。改用 `RtlMoveMemory`，本地写入/读回剪贴板验证通过。
- **关闭预发布通道后残留检查结果**：通道开启时检查出的「发现新版本（预发布）」提示与更新按钮在关闭通道后仍残留、可点击。开关切换后自动复位 harness 检查结果并给出通道状态提示；检查增加竞态防护（切换/连点后过期响应不再覆盖新状态）。

### 新增

- **插件操作收尾结果事件（`plugin:op:done`）**：插件更新 / 删除 / 启用结束后行内状态可靠刷新——成功清除「有新版本」残留提示并显示已更新版本；失败行内直接展示失败原因并保留「更新」按钮便于重试（此前失败路径无事件，行永久停留「正在更新插件…」）。
- **自动绕行 pnpm 供应链发布年龄校验**：lockfile 中其它插件（如 dsh-cost-meter）新发布未满 `minimumReleaseAge` 会卡死整条 pnpm 命令（`ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`），使无关的目标插件更新反复失败。识别后自动以 `--config.minimumReleaseAge=0` 临时跳过年龄校验重试一次（仅本次，不改 profile 配置），重试仍失败则原因附配置建议。
- **插件更新 / 删除启动失败分层自愈**：启动日志点名的嫌疑插件与本次操作无关时，不再回退无辜的目标插件更新——先禁其它嫌疑插件换取服务可启动，无效再兜底禁用全部用户插件，两级均无效才回退且失败原因写明与本次操作无关。

### 移除

- 无。

## v0.8.5

- **跨机导入的本地插件无法加载（dsh-ui-taste 实证，`ERR_MODULE_NOT_FOUND: Cannot find package '@deepseek-ai/dsh-settings'`）**：根因是导入副本的稳定落点 `<dshHome>/local-plugins` 位于 profiles 工作区树之外——dsh 的 loader 按 Node ESM 规则从插件**真实路径**上溯 node_modules，旧落点上溯链找不到提升的 `profiles/node_modules`（@deepseek-ai/dsh-settings 等官方 peer 依赖所在），插件加载失败。修复：①稳定副本落点改为 `<dshHome>/profiles/local-plugins`（上溯链命中 profiles/node_modules，peer 依赖可解析）；②新增旧落点自动迁移——spec 仍指向旧落点的副本迁移到新落点并改写 spec（历史版本遗留的「副本在但加载失败」状态导入/更新时自动修复）。

## v0.8.3

自 v0.8.2 起（三项改进：mac 本地插件重选仍未加载续查、日志页完整显示、禁用优先于版本回退）：

### 修复

- **mac 重选本地插件后仍未加载（R2 定案）**：待重指定插件重选目录时，若历史记录 bundled=false（源机未激活），重选事务只清记录、不把插件加回激活清单——spec 与 node_modules 均已就位但 harness 从未加载它，且无任何提示。现在**重选 = 显式激活**：无论历史 bundled 真假，重选一律补进 `dsh.profile.bundles`。
- **mac 旧服务进程不退出导致新配置永不加载**：`killServer` 对端口监听进程只发一次 SIGTERM；旧进程未退出时重启校验误判「端口已有可用服务」而跳过重启，插件重选/更新/导入的新配置不生效。现 SIGTERM 后轮询端口释放，仍存活时 SIGKILL 兜底（与 Windows taskkill /F 语义对齐）。
- **日志页内容不完整（三处丢失点）**：前端 4000 行 DOM 裁剪把最早写入的行静默丢弃；日志轮转后 offset 跳到新文件末尾，把「轮转后新写入的行」整体跳过（mac 每次服务重启都轮转）；轮转归档 .1/.2/.3 不参与展示，轮转前的历史从页面消失。现在日志页 = 归档（旧→新）+ 基础文件完整拼接，检测到轮转自动清空视图重载，清空日志一并删除归档。

### 变更

- **禁用优先、回退兜底**：更新 harness / 导入插件后服务启动失败时，先按启动日志点名禁用肇事插件；未奏效或无点名嫌疑时禁用全部已激活的用户插件再试，仍失败才回退版本。冷启动失败同样先尝试「禁用肇事插件保留当前版本」，都失败才恢复 LKG 旧版本。禁用只摘除激活清单并记录原因，可在关于页逐个重新启用。

### 移除

- 日志页 DOM 行数裁剪（与「完整显示所有已写入内容」冲突）。

### 新增

- **重置目标版本选择**：重置 Harness 时下拉可选官方已发布版本（仅提供早于当前运行版本的版本，默认选其中最新稳定版）；预发布通道版本以警示色标注，选中时提示与已装插件的兼容风险；当前版本识别失败或无更早版本时降级放行，按官方默认目标执行。
- **插件禁用 / 启用自愈**：更新、安装、删除插件或恢复导入后，若服务因某插件与当前核心不兼容而启动失败，自动「禁用」冲突插件（保留其文件与依赖声明，从 bundles 摘除并记录原因）后重启服务，不再整体回退；关于页展示禁用状态与原因，支持手动启用（启用后启动仍失败会自动重新禁用）。
- **本地插件更新**：插件行支持从本地目录选择新版本包，比对确认后覆盖更新（复用快照 / 回退 / LKG 管线）。
- **恢复 / 导入重构**：多个「恢复项」可先后入队、各自独立进度并逐项取消；批量共享自愈期间全局禁用恢复按钮；zip 解压支持中途停止（不再卡死）。
- **常规页「打开 Web UI」按钮**：服务运行时可一键打开 Web UI，指向服务实际运行端口（端口修改未重启的窗口期也正确）。
- **检查更新与重置同源**：npm 预构建形态的「检查更新」改为以 npm 已发布版本为准（与重置一致），修复 GitHub Release 领先/缺失 npm（如 0.1.2-rc.1 已发 npm、GitHub 无 Release）时两边版本不一致。
- **service_guard 增强**：启动前日志轮转留档（.1/.2/.3）、启动日志可疑插件定位、profile 依赖自动对齐重装、重启后健康校验窗口化与自动重试。

### 变更

- 恢复导入仅激活导出清单中列出的 bundles 覆盖名，不再合并源机的禁用列表与未激活依赖；恢复后的启动兼容由「禁用自愈」机制兜底。
- 重置流程文案修正为实际行为（停服 → 清空原目录 → 全新安装所选版本），移除旧描述「回退到上一个正常运行的版本」。
- 取消恢复按钮不再触发 3 秒后自动重启，改为保持禁用直至恢复任务真正结束。

### 移除

- 无用户功能移除（历史单一恢复槽由多任务队列取代，交互以「逐项恢复/取消」呈现）。
