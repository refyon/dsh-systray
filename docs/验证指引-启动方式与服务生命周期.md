# 验证指引：启动方式、后台服务生命周期与插件同步（v1.1.0-dev）

> 本文件是 2026-09-27 这轮改动（需求①~⑤）的实测清单，验证完可删或并入发布物料。
> 每项都写明「怎么操作 / 期望看到什么 / 出问题看哪里」。

## 0. 构建产物与换入

| 项 | 值 |
| --- | --- |
| 新 exe | `src\build\bin\dsh-systray.exe`（v1.1.0，含本轮全部改动） |
| SHA256 | `CD8C4C8A4DD1DDC810E1AE81BCBBB643DBA8AE558051E46BFCCF652773DBA6D7` |
| 当前运行的托盘 | 同一路径（用户实测中；重复构建会把在跑的映像改名为 `dsh-systray.exe~`，因此**换入新构建需再退出并重启托盘一次**） |
| 换入方式 | 托盘菜单 → 退出（选「停止并退出」）→ 重新双击 `src\build\bin\dsh-systray.exe` |

注意事项：

1. 托盘退出/切到 Desktop UI 都会停掉 `127.0.0.1:3080` 的后台服务；若当前正用 Web GUI，会断开该会话，
   属预期行为（改用官方桌面端后 GUI 走它自带的 Host，不受影响）。
2. 若托盘图标不出现/闪退，多半是产物完整性标签（本机工作区带 Low 标签）——用**提权 shell**执行
   `scripts\build.ps1 -Version v1.1.0` 重编（脚本末尾会把 `build\bin` 与 exe 标签提升为 High），
   或在提权 shell 执行：
   `icacls src\build\bin /setintegritylevel (OI)(CI)H` + `icacls src\build\bin\dsh-systray.exe /setintegritylevel H`

## 1. 需求①：desktop 形态隐藏 Web 板块、按需启停后台服务

准备：设置 → 常规 → 默认启动方式 → 选 **Desktop UI**（弹确认 → 确定）。

- [ ] **切换即停服**：切换后「后台服务」应停止——托盘菜单状态行显示「服务已停止」，
      `http://127.0.0.1:3080/` 不再响应；任务管理器里 node 进程退出。
- [ ] **Web 板块整块隐藏**：常规页只剩「开机自启动 / 界面语言 / 默认启动方式 / 官方桌面端」四张卡，
      后台服务状态、服务端口、Harness 目录、重置四块全部不可见。
- [ ] **帮助页按启动方式分内容**：desktop 模式下左侧仍有「帮助」入口，页内只有一张
      「Desktop UI 无法正常使用时」卡片（Web 鉴权卡片不显示），卡片含「切换到 Web UI」按钮；
      点按钮 → 弹确认 → 确定后后台服务开始启动、页面自动切成 Web 侧帮助（含「打开 Web UI」按钮）；
      web 模式下帮助页只显示「Web UI 需要重新鉴权」卡片（没有切换卡片）。
- [ ] **启动不再拉起服务**：托盘退出 → 以 desktop 为默认启动方式重启程序 → 托盘出现后
      **没有** splash 启动进度、3080 端口不监听、托盘状态行为「服务已停止」。
- [ ] **切回 Web 弹确认并启动**：下拉选 **Web UI** → 弹确认（说明会启动后台服务、首次可能较久）→
      确定后出现进度窗口（即使是开机自启拉起的进程也要可见）→ 就绪后托盘变「打开 Web UI」。
- [ ] **退出不再询问**：desktop 模式下托盘右键「退出」→ **不弹**「是否停止后台 Web 服务？」，
      直接退出；切回 web 模式后该询问恢复（web 模式下服务可能还在跑，保留/停止由用户决定）。

出问题看 `%APPDATA%\dsh-systray\logs\dsh-systray.log` 里的 `[service]` / `[startup]` / `切换到 Desktop UI` 行。

## 2. 需求③：常规页排序与板块归属

- [ ] 自上而下顺序为：**开机自启动 → 界面语言 → 默认启动方式 → 之后按启动方式显示板块**。
- [ ] desktop 模式：第 4 块是「官方桌面端」卡片（版本 / 运行状态 / 更新通道 / 安装位置 + 打开按钮）；
      web 模式：第 4 块起是 Web 板块（后台服务 / 端口 / Harness 目录 / 重置），且**没有**官方桌面端卡片。
- [ ] web 模式 + 未装桌面端时：启动方式下拉右侧出现「**安装桌面端**」按钮；装了以后自动收起。
- [ ] 开机自启动卡的副标题随启动方式变化（desktop：不启动后台服务）。
- [ ] 切到英文界面（界面语言 → English）检查以上文案均有英文，无中文残留。

## 3. 需求⑤：启动时「配置与实机不符」的询问

- [ ] 配置 `desktop` + 未装桌面端：重启程序 → 弹「配置为 Desktop UI 但未检测到官方桌面端」，
      三个按钮：**安装桌面端 / 改用 Web UI / 保持现状**。
      - 「改用 Web UI」→ 配置改写为 web + 后台服务启动；
      - 「保持现状」→ 配置仍是 desktop，但按 Web UI 运行（服务启动），下次启动不再重复询问；
      - 「安装桌面端」→ 下载官方安装包（进度走 splash）→ 启动安装向导。
- [ ] 配置 `web` + 已装桌面端：重启程序 → 弹「配置为 Web UI 但已安装官方桌面端」，
      两个按钮：**改用 Desktop UI / 保持现状**；选保持现状后不再重复询问。
      - 开机自启（`--autostart`）场景下**不弹**此询问（只记日志）。
- [ ] 配置 `auto` → 从不弹窗（跟随检测）。
- [ ] 显式改动启动方式后，之前的「保持现状」记忆失效（再次重启若仍不符会重新询问）。

配置文件在 `%APPDATA%\dsh-systray\config.json`，字段 `launchTarget` / `launchMismatchAck`。

## 4. 需求④：desktop 模式下删除插件不跑 Web 服务校验

准备：desktop 启动方式、后台服务处于停止状态。

- [ ] 关于页删除一个在线插件（例如测试用插件）→ 关闭设置窗口时确认应用 → 进度条走完 →
      弹窗汇总**不应**出现「服务已重启」，而应显示「已跳过后台服务的启动校验（桌面端重新启动后生效）」。
- [ ] 插件确实从 `~\.dsh\profiles\<profile>\package.json` 消失，`node_modules\<pkg>` 被移除，
      `dsh.profile.bundles` 中的激活声明被摘除。
- [ ] 全程 3080 端口始终没有服务被拉起（任务管理器无新增 node 进程）。
- [ ] 桌面端重新启动后该插件不再加载。

## 5. 需求②：桌面端环境的插件同步到 dsh-connect

准备：登录数据同步（设置 → 数据同步），官方桌面端已安装并登录同一账号。

- [ ] 在**桌面端内**安装一个在线插件（走桌面端自己的插件安装入口）→ 托盘「立即同步」→
      日志出现「插件对账补报：<插件>（账号上没有该插件的记录，desktop，本机 vX.Y.Z）」。
- [ ] 在托盘插件列表里该插件的环境列显示 `desktop`（同时装在两个环境时显示 `web、desktop`）。
- [ ] 另一台机器（或本机删掉该插件后）点「立即同步」→ 出现「有来自账号的同步改动待生效」，
      点「重启生效」后应用；应用进度文案为 `插件 <name>（desktop）`。
- [ ] **web 与 desktop 互不覆盖**：同一个插件在两边都装、只有 web 侧删掉时，
      web 记录变 remove 墓碑，desktop 记录保持 install。
- [ ] desktop 启动方式下应用同步改动：只落文件、不重启后台服务（弹窗/日志体现「重启桌面端后生效」）。
- [ ] 未登录时不产生本地残队（同步页显示未登录入口）。

服务端若拒绝 `plugin:desktop:*` 键，会在同步状态行显示同步失败原因——请把该原因回报（键格式
`plugin:<profile>:<name>` 与 dsh-connect docs/API.md §11 的合并键约定一致，profile 段本就存在）。

## 6. 导入/恢复按启动方式分派（本轮补齐）

准备：desktop 启动方式、后台服务停止；手上有一个含插件的导出包（设置 → 导出 里可先生成）。

- [ ] 导入页顶部出现 desktop 说明：「恢复只写文件、不启动后台服务做启动校验，插件改动在桌面端重新启动后生效」。
- [ ] 恢复插件项：进度条阶段文案为「正在校验导入的插件兼容性…（Desktop UI 不启动后台服务…）」，
      全程 3080 端口不监听、无新增 node 服务进程。
- [ ] 完成后汇总说明含「已跳过服务启动校验（Desktop UI…）」，且**没有**「服务已重启/校验通过」字样。
- [ ] 恢复会话/文件类：完成后同样不拉起后台服务（托盘状态行保持「服务已停止」）。
- [ ] 启动时的事务自愈照常工作：模拟「导入中途强杀」（恢复大包时结束托盘进程），再以 desktop 模式
      启动 → 日志出现 `恢复中断自愈` / 快照还原行，`~\.dsh\profiles\*\node_modules` 不会停在
      `.importbak` / `.dshbak` 状态（这是桌面端能否正常加载的前提）。
- [ ] web 启动方式下回归：导入照旧「拉起服务 → 启动校验 → 失败自动禁用/回退」。

## 9. 端口不可用（被系统保留 / 被占用）的恢复路径（v1.1.1）

> 现场：2026-09-28，3080 落在 Windows 排除端口段 3004-3103，`dsh web` bind 失败即退出；
> 旧收尾把它当插件问题（disable-all 用户插件 + LKG 回退），且从 Desktop UI 切回 Web UI 时必然复现。

准备：把「服务端口」改成落在系统保留段内的端口（本机复现最省事）：

```
netsh int ipv4 show excludedportrange protocol=tcp      # 例：3004-3103
```

- [ ] **启动即精确报错**：设为保留端口后重启服务 → **没有**「服务进程异常退出」，
      「常规 → 后台服务」卡片显示「服务端口 N 被系统保留（Windows 排除端口段），后台服务无法启动。」
- [ ] **不误碰插件**：全程日志**没有** `disable-all user plugin …` 与
      `lkg: boot failed … attempting self-heal`；该端口上始终没有被拉起的 node 进程。
- [ ] **一键换端口**：卡片下方出现「改用端口 18080 并启动」→ 点击 → 端口改写为 18080、服务启动、
      托盘变「打开 Web UI」。
- [ ] **从 Desktop UI 切回 Web UI 同样生效**：desktop 默认启动方式下，下拉选 Web UI（或帮助页
      「切换到 Web UI」）→ 原端口不可用时弹「后台服务需要监听 127.0.0.1:N，但该端口…」询问 →
      选「改用端口 N」→ 服务起来、页面自动切到 Web 侧帮助。
- [ ] **弹窗三个按钮都可用**：同一询问里
      「**重试**」→ 先用别的程序占住该端口再点，应重新探测并再次询问（日志
      `still unavailable after user retry`）；「**打开日志**」→ 打开日志目录、关掉后回到询问
      （最多两轮）；**关掉弹窗**＝暂不启动，状态留在失败并显示原因。
- [ ] **端口被占用**：用别的程序占住端口后重启服务 → 提示为「已被其它程序占用」，且托盘先尝试
      停掉占用者（日志 `[service] port … preflight: in use`）。
- [ ] **开机自启不弹窗**：`--autostart` 且端口不可用 → 不弹窗，日志
      `port … unavailable, silent launch: skip prompt`，托盘状态行显示失败原因。
- [ ] **回归**：正常端口下冷启动、切回 Web UI、设置页「重启后台服务」全部照旧。

出问题看 `%APPDATA%\dsh-systray\logs\dsh-systray.log` 里的 `[service] port … preflight`、
`启动失败：…（已跳过插件自愈与版本回退）`、`改用服务端口` 行。

单测覆盖（`go test -count=1 ./...`，见 `src/portcheck_test.go`）：端口占用/释放判定、
推荐端口挑选、WSA 错误码分类（10013/10048 与 POSIX 形态）、端口证据与插件证据互不串味、
`failKind` 前端契约。

## 10. 从下拉切回 Web UI 只弹必要的窗（v1.1.1）

> 现场：2026-09-28，用户在下拉里选 Web UI 后，除了「切换启动方式」确认与端口询问，还多弹了一次
> 「官方桌面端已不可用…**是否现在启动后台服务**」——那是给「偏好没变、桌面端被卸载」的实机漂移
> 用的询问，被 2 秒轮询误当成了漂移（日志 `[launch] desktop target unavailable …`）。

准备：启动方式为 Desktop UI、后台服务已停止（切到 desktop 时会自动停服）。

- [ ] **切换只弹一次确认**：下拉选 Web UI → 只弹前端「切换到 Web UI 会启动后台服务…确认切换？」
      → 确认后服务启动；**全程不再出现**「是否现在启动后台服务？」询问，
      日志**没有** `[launch] desktop target unavailable, fell back to web ui: asking user to start service`。
- [ ] **切换请求不被吞**：若已有启动流程在跑（例如刚冷启动过），日志出现
      `switch to web ignored: service bootstrap already running`，状态行随后反映真实服务状态——
      不再表现为「点了没反应」。
- [ ] **真实漂移仍会问**：desktop 启动方式下卸载官方桌面端（或在注册表/`/Applications` 里使其检测
      失效）→ 2 秒内弹一次「官方桌面端已不可用…是否现在启动后台服务？」→ 选「暂不启动」后
      **不再重复弹**（同一偏好下只打扰一次）。
- [ ] **不重复打扰**：接上一步，重启托盘后再触发同类漂移，仍只问一次。
- [ ] **回归**：「配置与实机不符」的启动询问（desktop 未装 / web 且已装）照旧只在启动时问一次；
      切到 Desktop UI 时的前端确认与停服行为不变。

单测覆盖（`src/launch_drift_test.go`）：显式改偏好不触发漂移询问、桌面端消失时询问一次且不重复、
基线记录当前偏好与解析结果（`go test -count=1 -run 'LaunchDrift|RememberLaunchTargetBaseline' ./...`）。

## 11. 插件清单/操作/导入按启动方式隔离（v1.1.3-dev）

> 需求：关于页「已安装插件」只显示**当前启动方式**对应环境的插件（Web UI → `profiles/web`，
> Desktop UI → `profiles/desktop`）；行内「更新/删除/启用/检查更新/更新…」只改该环境；
> 导出与导入/恢复的插件同样只针对该环境（导入页插件项下方有小字说明）。
>
> 例外（保持原定义）：**重置**仍然清空全部 profile；**账号同步**不区分 profile——两套环境各一条
> 记录、都要能拉取/补报，因此重置后在另一台机器（或本机）点「立即同步」即可把两套环境的插件
> 一起同步回来（`dsh-systray` 侧只有「关于页清单 + 行内操作 + 导入/恢复」按环境隔离）。

准备：两套环境都装过插件（Web 环境装一个，桌面端内装另一个），并记下两边的
`%DSH_HOME%\profiles\web\package.json` 与 `...\profiles\desktop\package.json`。

- [ ] **清单按环境过滤（Web）**：启动方式为 Web UI → 关于页插件卡片副标题为「仅显示 Web UI 环境的插件」；
      清单里**没有**只在桌面端装过的插件；同名插件在两套环境版本不同时，显示的是 Web 环境的版本。
- [ ] **清单按环境过滤（Desktop）**：切到 Desktop UI（会停后台服务）→ 副标题变「仅显示 Desktop UI 环境的
      插件」，清单换成桌面端那套；Web 环境独有的插件消失，且**不再**出现「环境 web、desktop」这类合并标注。
- [ ] **行内操作只改当前环境**：Web 启动方式下对同名插件点「更新」（登记 → 立即应用）→ 只有
      `profiles/web` 的 `package.json` / `node_modules` 变化，`profiles/desktop` 下同名包内容与时间不变。
- [ ] **待应用变更记住环境**：Web 启动方式下登记一条更新（先不应用）→ 退出托盘 → 以 Desktop UI 启动
      → 应用该变更后仍是 `profiles/web` 变化、`profiles/desktop` 不变（配置里该条带 `"profile":"web"`）。
- [ ] **导出同口径**：Desktop 启动方式导出（勾选插件）→ 包内 `manifest.json` 的 `plugins.profile` 为
      `desktop`，`plugins.zip` 内前缀为 `profiles/desktop/node_modules/`（Web 启动方式则为 `web`）。
- [ ] **同环境导入**：Web 启动方式导出 → 另一份数据目录以 Web 启动方式导入插件项 → 插件进 `profiles/web`。
- [ ] **跨环境导入改写落点**：把 Web 环境导出的包在 **Desktop 启动方式**下导入插件项 → 导入页插件项下出现
      小字「插件只恢复到 Desktop UI 环境，Web UI 环境的插件不受影响。」；恢复后插件文件出现在
      `profiles/desktop/node_modules/<插件>`，`profiles/web` **完全没有被写入**；冲突询问按 desktop 环境的
      已有内容计数。
- [ ] **回归**：会话/文件目录的导出导入、待应用变更的撤销与「立即应用」、插件删除的会话风险提示、
      重置 Harness 的插件统计、dsh-connect 同步（两套环境各一条记录）照旧。

出问题看 `%APPDATA%\dsh-systray\logs\dsh-systray.log` 里 `登记待应用变更 …`、`批量处理插件`、
